# Image Playground 界面重构方案

日期：2026-09-13。状态：方案已获确认并完成本地实施；实际改动、验收结果和未验证范围见 [实施验收记录](2026-09-13-minimal-ui-implementation.md)。下文保留规划阶段的分析与原始验收清单，未勾选项不等同于最终实施状态。

本方案以本地 `E:\agentlearn\前端代码\minimal-starter-vite-ts-main` 的主题与布局为设计参考，服务于当前 Image Playground 的图片创作流程。源码核查时的当前提交为 `dba96ea`；该提交仅用于记录分析上下文，不代表本次创建了备份或提交。

## 1. 推荐方向与范围

将现有界面整理为“对话导航 + 图片工作区 + 底部创作面板”，采用 Minimal 的绿色点缀、蓝灰文字、柔和阴影与统一圆角。图片和创作输入成为视觉重点，常用动作直接可见，低频参数按组收纳。

沿用 React、TypeScript、Vite、Tailwind 和 Zustand。在当前组件上统一设计变量与展示结构，承接现有任务运行、API 配置、IndexedDB、全局输入草稿和导入导出逻辑。

这次设计包括主工作台、图库与收藏入口、创作输入、任务状态、设置、图片详情，以及移动端适配。参数矩阵、图片对比、演变关系、遮罩编辑、反推提示词和命令面板均纳入功能保留清单。账户、团队、通知、统计仪表盘等模板演示内容不属于本项目的本轮需求。

规划阶段产出为方案文档和独立的交互示意；示意中的图片、对话和排队记录都是示例内容。示意不读取浏览器中的真实项目数据，也不调用图像接口。

### 为什么采用这条路线

| 路线 | 收益 | 代价 | 本方案选择 |
| --- | --- | --- | --- |
| 在现有组件中实现 Minimal 的视觉规范 | 功能承接直接，可按区域验收和回退 | 需手动整理颜色、组件状态和布局 | 推荐 |
| 将界面整体迁入模板的 MUI + Emotion 体系 | 可直接使用模板的部分组件实现 | 涉及全局样式、主题、弹层、路由与依赖迁移 | 不作为第一轮实施路线 |

参考项目的六个 Dashboard 页面均使用 `BlankView`，它主要提供主题、导航和基础组件，图片工作台的内容布局需要在本项目中设计。

## 2. 设计目标与信息层级

1. 打开页面即可确认“正在看哪个对话或作品范围”。
2. 输入区集中完成提示词、参考图、模型和尺寸配置；生成按钮和保存目标始终清楚。
3. 图片大于文字，状态大于装饰，常用操作大于低频配置。
4. 桌面可连续浏览、生成和复用；手机能完成同样的核心流程。
5. 布局变化不改变任务归属、筛选范围、草稿保存、批量操作和图片编辑语义。

这些是本次设计目标，不是已经完成的可用性实验结论。尚未对两套实际运行界面做用户测试或性能测量。

## 3. 主工作台布局

### 3.1 桌面结构

| 区域 | 内容 | 建议规格 |
| --- | --- | --- |
| 左侧导航 | 品牌、新建创作、全部作品、我的收藏、近期对话、设置 | 展开 256px，折叠 72px |
| 顶部工具栏 | 当前范围/对话名称，命令搜索入口、帮助、主题 | 高 64px；模型信息降为次要信息 |
| 工作区标题与筛选 | 页面标题、可见结果说明、关键词、状态、收藏分类 | 水平留白 24px；窄屏换行 |
| 图片工作区 | 普通任务卡片与参数矩阵 | 内容最大宽度 1440px；卡片间距 20px |
| 底部创作面板 | 保存目标、提示词、参考图、常用参数、生成 | 宽度跟随主内容列，内部最大宽度 1040px |

应用外壳建议使用两列布局；右列内部划分顶部工具栏、可滚动工作区和创作面板三个区域。桌面让创作面板占据真实布局空间，图片区承担剩余高度。

这样可通过同一布局列控制侧栏折叠后的内容宽度，减少当前输入栏基于视口居中与侧栏宽度计算偏移的耦合。实施时一并移除旧输入栏偏移类和主内容固定底部占位，避免双重留白。工作区保留 `data-home-main`、`data-drag-select-surface` 等现有行为锚点。

示意为便于在对话中展示，使用自然文档流呈现底部面板；真正应用中的桌面滚动与停靠行为需在实施阶段验证。

### 3.2 导航设计

导航顺序：品牌 → 新建创作 → 全部作品/我的收藏 → 近期对话 → 设置。

- “新建创作”是主要动作，使用实色按钮；文案可以改变，内部仍使用现有新建/复用空对话规则。
- “全部作品”承接现有图库能力。“我的收藏”是全图库收藏的快捷入口，不创建新的存储实体。
- 对话列表继续支持重命名、删除和既有排序；保留对话颜色与任务数，仅将它们设为次级信息。
- 选中项使用浅绿色底色、深绿色文字和图标，不依赖颜色单独表达当前项。
- 折叠后保留新建、图库、收藏、设置入口和展开按钮；长对话列表通过展开导航访问。图标入口必须可聚焦并具有可访问名称。
- 设置位于导航底部。帮助、主题、命令搜索在顶部，各有明确功能。

### 3.3 导航与筛选的明确语义

以下是实施目标。其中“我的收藏快捷入口”和“范围文案”是本方案新增的界面组织方式，底层继续使用现有字段和动作。

| 用户动作 | 展示范围 | 草稿与任务归属 | 搜索/状态/收藏处理 |
| --- | --- | --- | --- |
| 点击全部作品 | 所有对话的作品 | 保留当前激活对话 | 保留搜索与状态；清除收藏与分类筛选 |
| 点击我的收藏 | 所有对话的已收藏作品 | 保留当前激活对话 | 保留搜索与状态；启用收藏，清除分类 |
| 点击某条对话 | 该对话的作品 | 改变任务写入目标；保留当前全局输入草稿 | 延续现有搜索和筛选规则；标题旁显示仍生效的条件 |
| 点击新建创作 | 新建或复用的空对话 | 由现有 store 动作更新激活项；保留全局输入 | 延续现有动作的筛选处理；避免在新入口中另写一套规则 |
| 选择收藏分类 | 当前范围内的该分类作品 | 不改变对话归属 | 与“仅收藏”开关互斥，沿用已有 setter |
| 范围或筛选实际变化 | 新条件匹配的记录 | 不修改历史任务 | 清除多选；重复点击未改变条件的当前入口不应无故清空选择 |

`galleryView`、`activeConversationId` 和现有筛选字段是状态来源；导航选中态从它们推导，避免再持久化一份相互矛盾的“当前页面”。搜索条件持续可见，并提供清除筛选动作。

图库仍可创作。输入面板常显“生成到：产品摄影”等目标对话名称；点击该名称可回到对应对话。不存在有效目标时显示“提交后创建新对话”，具体归属仍由现有提交流程决定。

源码核实：当前 `prompt`、`inputImages`、`params` 是单份全局输入，`setActiveConversation` 不保存/恢复每对话独立草稿。第一轮沿用这一行为。每对话草稿若后续需要，应作为单独功能设计数据结构、迁移与恢复规则，不能当作已有能力。

## 4. 图片与任务工作区

### 4.1 卡片结构

每张卡片代表一个任务；多输出任务显示真实输出张数，不能因视觉改造把一张任务卡误拆为多个独立任务。

从上到下排列：图片封面 → 最多两行提示词 → 尺寸/模型简要信息 → 操作区。全图库中增加可点击的所属对话标签。详细参数与 API 实际返回参数继续在详情中展示。

- 预览画布建议默认 4:3，图片使用 `contain` 保留完整构图；空余区域使用中性色。生成图本身的像素和比例不变。第一版不加入瀑布流，以减少排序、框选与矩阵布局的交互变化。
- 收藏、多选、查看详情为直接入口；复用提示词、编辑输出、删除等整理到清楚可见的更多菜单或详情动作区。
- 拖拽继续使用独立手柄，仅在单对话、无筛选、无矩阵、未触发显示上限且任务数足够时启用，保留键盘排序能力。
- 普通点击卡片先按原规则清除多选再进入详情，Ctrl/⌘ 点击切换选择；收藏、菜单、选择框和手柄阻止冒泡。触屏不依赖悬停显示关键操作。
- 保留封面懒加载、对象 URL 管理、任务展示上限和选择范围约束。

### 4.2 状态设计

| 状态 | 展示 | 可用动作 |
| --- | --- | --- |
| 空对话 | 简洁创作引导与少量可填入提示词的示例 | 输入提示词、添加参考图 |
| 图库无作品 | 说明作品会在生成后汇总到此处 | 新建创作 |
| 搜索/筛选无结果 | 明确显示当前条件与“清除筛选” | 清除条件；保留输入草稿 |
| 排队/执行中 | 文字状态、现有计时或阶段信息 | 依运行时能力取消；不显示估算成真实的百分比进度 |
| 已完成 | 图片和任务摘要 | 详情、收藏、复用、编辑 |
| 失败 | 简明原因、错误详情入口 | 重试、修改输入；保留错误信息 |
| 取消/等待重试 | 使用现有数据可表达的状态与说明 | 按任务真实状态提供动作，不增加虚构状态字段 |
| 本地数据初始化失败 | 原有常驻错误提示与恢复引导 | 与“新用户空库”区别展示 |

### 4.3 矩阵、多选与专业功能

参数矩阵继续占据整行，保留 X/Y 轴标签、单元对应关系、补跑、批次笔记和整图导出。宽矩阵允许在其自身容器内横向滚动，普通页面不横向溢出。X 轴至少两个值，Y 可省略且不能与 X 同维度；筛选后仅剩一个成员时仍按现有规则降为普通卡片。

同一格补跑可保留多条历史任务，只展示最新代表任务；矩阵进度按格计算，整批取消按成员任务计算。“格数”“任务数”“输出图数”分别命名，避免用同一个数量标签混淆，`n` 作为参数轴时也须遵循现有计算。

多选后在工作区顶部出现批量操作栏，展示选中数量、清除选择、收藏、对比、反推、取消和删除等现有可用动作。创作面板与提示词保持挂载，多选不会清空草稿。实现时优先移动/适配现有 `SelectionActionBar`，不复制其任务筛选逻辑。

“选择当前显示的任务”与矩阵的“选中整批”采用不同的明确范围：前者只取已呈现普通卡片和格子代表任务；后者保留现有整批成员语义，可包括同格的历史重试记录，并保留批外已有选择。整批入口显示成员任务数，批量栏及破坏性操作确认说明包含的批次与历史成员；不得用“页面可见”文案掩盖整批范围。

统一计算“显示块/格子代表任务/已显式选中批次成员”三个集合，分别用于普通全选、框选和整批动作，再计算各动作的合法目标。尤其要覆盖矩阵在显示上限处按整块截断的情况，不能仅凭 `slice(0, limit)` 推断页面可见任务，也不能把用户明确选中的整批历史成员一律当作残留选择丢弃。该范围整理属于实施时需单独覆盖测试的交互改动。

取消整批保留记录并允许补跑；对照图导出沿用至少一格完成的门槛，导出中避免重复点击，并保留批次笔记。对比继续仅对 2–4 个已完成且有输出的任务启用；批量取消只处理仍在执行的任务。

图片对比、演变关系、网格图导出、批量反推继续使用现有独立弹层；本轮主要统一工具栏、标题、标签和表面样式。

## 5. 底部创作面板

### 5.1 常用层与进阶层

面板按三个区域组织，降低单行参数拥挤度。

1. 顶部小行：生成目标对话、参考图数量和已启用遮罩提示。
2. 输入主体：带明确标签的提示词输入框；参考图存在时显示缩略图及其操作。支持原有文件选择、粘贴和拖放。
3. 底部工具行：添加参考图、模型、尺寸、风格、更多；右侧为带文字的“生成”按钮。

模型菜单保留配置切换和模型选择两个层级。尺寸入口归组呈现比例、分辨率与自定义尺寸，继续调用现有尺寸选择和校验逻辑。

“更多”包含参数网格、提示词片段、AI 优化、反推提示词、质量/格式/数量等高级参数以及重置。采用分组菜单，打开后转交原有弹层；菜单互斥，不堆叠两层参数面板。遮罩等影响普通提交的配置在关闭菜单后仍须可见。

参数网格沿用现有“在网格弹层配置 → 点击生成网格 → 关闭弹层”的独立提交流程。底部普通生成按钮不会因此进入持久的“网格模式”；网格预估数量和生成目标放在网格弹层内明确展示。

### 5.2 生成与草稿交互

- 按钮使用“生成”或“应用遮罩”文字表达当前动作；数量以现有展开与校验结果为准，不用 `n` 单独猜测真实任务总数。
- 未配置必要接口时显示“配置 API”并打开现有设置面板；无需把用户带离创作上下文。
- 提交中的禁用逻辑使用当前 `submitting` 等真实状态，避免重复入队；执行中的任务不会无故禁用下一轮合法提交。
- 保留 Ctrl/⌘ + Enter、输入法组合输入处理、16 张参考图上限和既有通配展开规则。
- 切换对话与新建创作保留当前全局提示词、参考图和参数，仅更新生成目标；侧栏折叠、主题切换、打开详情不会重挂载输入容器导致内容丢失。
- AI 优化保持新旧提示词对照与主动采用；“重置全部输入”继续明确列出将清空的内容并确认。

### 5.3 高度与滚动

桌面将面板作为右列底部区域，不覆盖任务卡片。短提示词时面板保持紧凑；长提示词和大量参考图设内部合理高度上限，避免挤掉整个工作区。实施时根据浏览器可视高度验证，不写死所有设备共用的总高度。

移动端输入面板默认紧凑，展开后显示完整参数。使用现有移动手势和安全区处理，验证软键盘弹出、横屏和低高度窗口中的提交可达性。主页面避免新增多个相互争抢手势的滚动容器。

## 6. 设置、详情和编辑器

### 设置

继续基于现有 `Modal`。桌面建议最大宽度 960px，左侧 168px 分类导航，右侧表单；手机改为单列与顶部分类选择，保存操作保持可达。

分类为：图像 API、提示词优化、反推提示词、运行参数、收藏分类、外观、数据管理。三套 API 的独立配置继续独立；不得为了布局合并模型与密钥。

保留现有 draft、保存、取消和未保存变更处理。收藏分类管理和数据导入/清理等即时动作必须明确其生效时机，不能因放入同一个设置面板而暗示都等待“保存”。外观分类第一轮只整理现有浅色/深色/跟随系统能力；示意中的主题色和留白调整属于评审工具，不自动转化为新增用户设置。

### 图片详情

桌面采用图片为主、信息为辅的两列布局，建议图片约占 2/3，右侧信息区 320–380px；手机纵向排列。提示词、请求参数、实际返回参数、参考图、遮罩和演变关系分区展示，保留差异高亮。

底部动作区保留下载、复制、复用、继续编辑等既有能力。放大查看继续进入当前 Lightbox，保留缩放、平移和键盘导航。

### 遮罩与其他弹层

遮罩编辑器第一轮只调整工具栏、面板和按钮样式；画布坐标、指针交互、撤销重做及图像预处理沿用原实现。统一 `Modal`、焦点陷阱、Escape 栈、滚动锁和浮层定位机制，不能额外引入一套 MUI 弹层栈。

## 7. 视觉规范

以下为推荐设计值，允许在主界面评审后微调。颜色通过语义变量管理，而非逐个组件散落替换。

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | `#F4F6F8` | `#141A21` |
| 卡片/导航表面 | `#FFFFFF` | `#1C252E` |
| 次级表面 | `#F9FAFB` | `#28333F` |
| 主要文字 | `#1C252E` | `#F4F6F8` |
| 次要文字 | `#637381` | `#B2BCC8` |
| 分隔线 | `#DFE3E8` | `#34424F` |
| 品牌点缀 | `#00A76F` | `#5BE49B` |
| 主按钮背景 | `#007867` | `#5BE49B` |
| 主按钮文字 | `#FFFFFF` | `#0B3023` |

品牌点缀沿用参考模板绿色，浅色实色按钮适当加深。按上述不透明色对计算，浅色主按钮白字对比度约 5.41:1，浅色次要文字在白色表面约 4.88:1；深色按钮约 8.91:1。实际实现仍需验证悬停、禁用、半透明背景和图片覆盖层，以上计算不等于整站可访问性验收。

- 字体：延续项目中文字体栈，使用 HarmonyOS Sans SC 和系统中文字体回退；不因套用英文模板额外引入一组远程字体。
- 标题：页面 24px/600；区域标题 16px/600；正文和控件 14px；辅助说明 12px。手机输入控件至少 16px，避免缩放与难读。
- 间距：4/8/12/16/24/32px 基础级距；卡片间距 20px 为布局专用值。
- 圆角：按钮与菜单项 8px，卡片和普通弹层 16px，创作面板 20px；标签可使用胶囊形。
- 阴影：卡片为轻柔静态阴影，菜单与弹层更强一级；深色主要依靠表面明度和边线区分层次。
- 动效：悬停 120–160ms，导航折叠和弹层 160–220ms，遵循 reduced-motion；弱化现有持续环境光和大量错落入场。
- 图标：第一轮统一现有图标尺寸、描边和对齐，保留本地图标来源；无需为视觉改造同时迁入多套图标库。
- 触控：重要动作有效点击区域至少 44px；键盘焦点轮廓持续可见；选中和错误状态同时有文字或图标。

绿色为推荐默认。蓝色可作为评审备选，通过同一套变量替换；两者不改变页面结构和功能。

## 8. 响应式规则

| 可用视口 | 导航 | 工作区 | 创作面板 |
| --- | --- | --- | --- |
| ≥1280px | 默认展开，可折叠 | 通常 3 列；宽度充足可 4 列 | 完整工具行，跟随右列 |
| 1024–1279px | 展开/折叠依用户选择 | 通常 2 列，按内容宽度决定 | 参数允许换行 |
| 768–1023px | 建议默认紧凑导航 | 1–2 列 | 常用操作可见，进阶收纳 |
| <768px | 抽屉 | 默认 1 列；标题和筛选换行 | 紧凑/展开两态，处理安全区与软键盘 |

卡片列数最终以扣除侧栏后的实际内容宽度为准，目标最小卡宽约 260px；窄于该宽度时允许单列缩小，不强迫页面横向滚动。超宽屏内容居中，避免图片卡片无限拉大。

沿用当前 768px 移动交互边界优先实施；平板紧凑导航是新的展示规则，必须与用户的显式折叠选择区分，不能在 resize 时覆盖持久化偏好。手机抽屉和参数面板沿用既有关闭、焦点与滚动锁机制。
